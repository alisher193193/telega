# Правила работы с проектом

- Не читать, не показывать и не коммитить .env.
- Не выполнять docker compose down -v.
- Не удалять и не пересоздавать PostgreSQL volume.
- Не выполнять DROP DATABASE, DROP SCHEMA и alembic downgrade без отдельного разрешения.
- Не изменять уже применённые миграции.
- Новые изменения структуры выполнять новой миграцией Alembic.
- Миграции запускать через сервис bot: `docker compose run --rm bot alembic upgrade head`.
- В проекте существуют сервисы bot и postgres; сервиса web нет.
- Денежные значения рассчитывать через Decimal и хранить как NUMERIC.
- Основную бизнес-логику не помещать в Telegram handlers.
- Финансовые и составные операции выполнять транзакционно.
- Не удалять финансовые и рабочие записи физически — использовать отмену или корректировку.
- Перед изменениями проверять git status и сохранять пользовательские изменения.
- Не выполнять git commit и git push без подтверждения пользователя.
- Все даты в БД хранить timezone-aware, отображать в Asia/Almaty.
- После изменений запускать compileall и подходящие тесты.
- Не запускать интеграционные тесты против рабочей базы без проверки их изоляции.
